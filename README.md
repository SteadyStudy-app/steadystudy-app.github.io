# SteadyStudy — Prototype v0.2.2

スマホ・PC対応、アカウント不要の学習プランナー。実行時の外部ライブラリ、CDN、API、アクセス解析はありません。教材・目次・計画・実績はIndexedDBに保存します。ライト／ダーク、6種類のアクセントカラーを選択できます。

## GitHub Pagesで公開する（ビルド不要）

公開用ファイルは `dist/` にまとめています。ZIPの解凍やビルドは不要です。

1. このプロジェクトの `dist` フォルダを開きます。
2. GitHubで公開用リポジトリを作成します。GitHub Freeの場合はPublicを選択します。
3. リポジトリの **Add file → Upload files** を開き、`dist` 内のファイル・`assets`フォルダをまとめてドラッグします。フォルダ自体ではなく、中身をアップロードします。
4. **Commit changes** で保存します。リポジトリの一番上に `index.html` があることを確認します。
5. **Settings → Pages → Build and deployment** で、Sourceを **Deploy from a branch**、Branchを **main**、フォルダを **/(root)** にして **Save**。
6. デプロイ完了後、表示された `https://ユーザー名.github.io/リポジトリ名/` を開きます。HTTPSで利用してください。

`.nojekyll` がファイル選択に出ない場合でも、今回の通常のファイル名はJekyllで除外されないため表示できます。推奨は `.nojekyll` も含めてアップロードすることです。

`dist` には配信に必要なファイルだけを入れています。プロジェクト直下にはソース・テスト・開発スクリプトがあります。公開時にバックアップJSONや個人データをリポジトリに入れないでください。以前のZIPは旧版です。今後は `dist` の内容を使用してください。

## 使い方

- 最初は「サンプルで試してみる」を押すと、教材2冊、学習計画、過去の実績を追加できます。実データと同じように操作できます。
- 教材画面から教材名・科目・ページ／問題範囲・推定時間を登録します。章・節は `節名, 開始, 終了` の形式で1行ずつ任意入力します。
- 計画画面で教材、開始・終了日、曜日別の時間、均等／漸増配分を指定します。0分の曜日には配置しません。
- 教材ごとに今回の開始・終了番号を指定できます。章・節を選ぶと、その範囲が自動入力され、さらに番号を調整できます。両端を含む範囲です（p.20〜45は26ページ）。
- 指定範囲の計画済み・完了済み部分は除外します。入力画面とプレビューで、指定量・対象量・重複除外量を確認できます。範囲外は後から別の計画に使えます。
- ほかの計画の予定時間と、再計画時に保持する完了部分の予定時間を差し引いて配置します。入力した曜日別上限は、既存の予定も含めた目安です。
- プレビューを確認して保存します。未配置の範囲は警告し、計画内に保持します。
- タスクの「＋」から、先頭から何ページ・何問できたか、実際の時間と日付を記録します。
- 「残りを組み直す」で完了部分と履歴を保持し、未完了・未配置の範囲を再配置します。プレビュー後に適用します。
- 設定からベース・アクセントカラー、バックアップ保存・復元、データ削除を利用できます。

## 保存とプライバシー

- 同じ端末・ブラウザのプロファイル・オリジンごとに独立したデータです。自動同期はありません。
- ブラウザ内の保存は暗号化バックアップの代わりにはなりません。端末故障、ストレージ削除、容量不足等で失われる場合があります。
- バックアップは**暗号化していないJSON**です。個人の学習データとして安全に保管してください。復元は整合性検査と確認後に全置換します。
- 永続保存の申請機能はブラウザによって結果が異なり、消失しない保証ではありません。
- GitHub Pagesは配信時にGitHub側がセキュリティ目的でIPアドレスを記録します。アプリ自体から学習データを送信する処理はありません。
- 同じ `ユーザー名.github.io` 配下のプロジェクトはオリジンを共有します。別の信頼できないアプリを同じオリジンで配信しないでください。独立した専用ドメイン／サブドメインの利用がより適切です。
- 公開URLのドメインが変わると保存領域が変わります。移行前にバックアップし、新しいURLで復元してください。

## PWA・オフライン

初回はオンラインで開いてください。設定画面に「オフライン用のアプリを保存済み」と表示された後は、キャッシュ済みのアプリがネット接続なしでも動きます。iOSはSafariの共有→ホーム画面に追加、Android／PCはブラウザのインストール機能を使います。ブラウザやOSによって表示は異なります。

更新は新しいファイルを同じ場所に上書きします。**更新時は `sw.js` のCACHE名（例：`steadystudy-v2`）を変更**してください。次回アクセスで更新がダウンロードされます。すべてのSteadyStudyタブ／アプリを閉じて開き直すと適用されます。データベースは削除しません。IndexedDBのスキーマを変更する場合は、別途移行処理が必要です。

## 開発

依存インストールやビルドは不要です。実装はES ModulesのJavaScript、HTML、CSSです。GitHub Pagesにそのまま置けることを優先しています。

```sh
npm test
npm start
# http://127.0.0.1:4173/
npm run package  # distフォルダを更新（ZIPは作成しません）
```

Node.js 22以降・Python 3が必要です（開発・テスト時のみ）。`file://` のダブルクリックではES Modules、IndexedDB、Service Workerに制約があるため、HTTPサーバーまたはGitHub Pagesで開いてください。

## 構成と制限

- `engine.js`：DOMやストレージに依存しない計画生成。節優先の整数単位分割、教材内順序、曜日上限を扱います。配分は目標であり厳密な均等・単調増加は保証しません。全条件を満たす最適解を探索するものではなく、収まらない範囲は警告します。
- `store.js`：IndexedDBトランザクション、バックアップの形式・参照・重複検証、別タブでの更新検出。
- `app.js`：画面、入力、学習記録、再計画、設定。
- `sw.js`：バージョン単位のアプリキャッシュ。学習データはキャッシュとは別のIndexedDBです。
- 教材は最大10,000単位、計画期間は最大731日です。
- 進捗はタスク先頭から順番に記録します。記録の取り消し・修正、任意タスク固定は未実装です。1つの計画では、教材ごとに1つの連続範囲を選べます。離れた章・節は別々の計画として登録してください。
- 計画で使用中の教材は名前・科目のみ編集できます。学習実績のある計画の削除は履歴保護のため制限しています。必要な場合はバックアップ後に全データ削除を利用できます。
- 画像OCR・クラウド同期・通知・暗号化バックアップ・ログイン・課金は未実装です。
- バックアップリマインダーは最終書き出しから7日後に表示します。ファイルが実際に保管されたかをブラウザから保証することはできません。
- GitHub Pagesの商用SaaSに関する利用制限に従ってください。有料サービス化する際は配信先を再検討してください。

公式資料：[GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) / [公開ソースの設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) / [利用制限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

## アイコンを変更する

`assets/icon.svg` がロゴの元データです。画面内ロゴはSVGの形を使い、アクセントカラーで表示します。元のSVG自体の色は変更しません。

PWA・iOSホーム画面用PNGと小さいファビコンを更新する場合は、開発環境で `node scripts/icons.mjs` を実行します。Sharpが必要です（Codex同梱ランタイムでは利用可能。それ以外では `npm install --save-dev sharp`）。`python scripts/icons.py` は同じ処理を呼ぶ互換用コマンドです。

その後 `python scripts/package.py` で公開用 `dist` フォルダを更新します。PNG生成用のライブラリはサイト利用者には不要です。SVGを書き換えた際はService Workerのキャッシュバージョンも上げてください。
